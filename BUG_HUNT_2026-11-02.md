# Bug hunt, 2026-11-02: findings and suggested fixes

A read-only review of kurtkode's plumbing: the LLM wire layer, the agent loop and context management, tools and the
sandbox, git and MCP, sessions and snapshots, the CLI, the macOS app, and the infrastructure and eval harness. Nothing
was built, run or changed. Seven area reviews (one per subsystem) produced 131 candidate findings; the ones marked
**[verified]** below were re-read against the source by the author of this document, the rest are the area reviewer's
reading. Line numbers are working-tree lines at commit 8e62b04 with the uncommitted real-task edits present.

**Left out on purpose.** The uncommitted hunks of the real-task effort (`BashTool.environment(_:)`, `SandboxPolicy.
cacheVariables`, the Go test set-aside in `TaskBankReal`), except where a finding notes a design consequence of them.
Anything TODO.md already lists. The cost measurements themselves. Where an eval-harness finding changes what a stored
run means, it is flagged, not fixed: when to apply it is the measurement effort's call.

**How to read this.** Part 1 is a prioritized fix list, grouped by what goes wrong for the user. Part 2 is cross-cutting
design improvements that would close whole classes of these at once. Part 3 is the full list by area, with file:line,
scenario and fix, for whoever picks an item up.

**Behavior changes the user will notice, and decisions to confirm:**
- `-p` with a prompt now reads a pipe to its end (printing a note after 500 ms). A CI job that leaves stdin open and
  never writes now waits instead of continuing; run it with `< /dev/null`. The old code chose the opposite trade-off.
- In the app, ⌘↩ while typing in the composer no longer allows an approval card; card keys wait 0.5 s after a card
  appears; one kind of card shows at a time.
- A word after options that names a subcommand (`kurtkode -p inspect`) now runs the subcommand; use `--` for a prompt.
- A model spec whose endpoint prefix names no endpoint is refused on a keyed or remote default endpoint.
- Plain-http MCP servers with a token, other than on loopback, are refused. Cross-origin redirects are refused.
- `git gc`, `repack`, `prune` and large fetches fail inside a sandboxed worktree.
- Grep's content mode sorts by path for stable paging, which makes ripgrep single-threaded there.
- Project MCP servers whose config contains `${…}` are asked about again (their fingerprint changed).
- After a sandboxed (Full Auto) stretch, switching to Ask drops carried exports like a venv's PATH until re-exported.
- Applying a stash keeps it; drop it explicitly.
- Nudges appear in the app transcript as a small "note to the model" caption.

**Left for later:** P4, Part 2's design items not already covered (deny-default mach-lookup, approvals as a pinned
bar, the streaming-row split), and the size budget for shadow repositories. P3 is fixed (next section).

## Part 2. Design improvements that close whole classes

1. **The sandbox models file paths, not actions.** Allow-default with path and socket denies leaves every IPC broker open (cfprefsd, launchd, LaunchServices, AppleEvents). Deny-default `mach-lookup` with an allow list is the fix that makes items 6 and 7 moot and stops the "sandboxed command edits kurtkode's own settings" family for good.
2. **Nothing kurtkode trusts should live where sandboxed commands can write.** Attempt checkpoints and the `-after` env snapshot are in TMPDIR; the Go cache is shared. One rule, one home (Application Support), one audit.
3. **Check paths after opening, not before.** `O_NOFOLLOW` per component or `F_GETPATH` after open removes both the nonexistent-path symlink hole (item 5) and the resolve-then-write window.
4. **Approvals should show exactly what they grant.** MCP env and headers, carried exports, the subagent's reason, and a suggested rule no broader than the command seen. A fingerprint over hidden fields is an approval of something the user didn't read.
5. **Bash deny rules are advisory today.** Interpreter one-liners (`python3 -c`, `perl -e`, `node -e`, `awk system()`, `osascript -e`), scripts the agent just wrote, and unknown wrappers (`arch`, `gtimeout`, `script`, `flock`, `sandbox-exec`, `ssh host cmd`, `xcrun`) all pass `Bash(rm:*)`. Opaque-by-default for interpreter `-c`/`-e` under a deny rule, and treating any unparsable wrapper argument as opaque, would make the rules mean what they say.
6. **One session-lock helper for both front ends.** Everything that appends or restores (send, retry, `!cmd`, compact, rewind, retract, rename, folders) goes through `withSessionLock { reload(); … }`.
7. **A fixed capture set per session for snapshots.** Size skips are already sticky; ignore rules and tracking changes should be too. Then "added" means added, and rewind can't delete a pre-existing file.
8. **Record kurtkode's own restores as snapshot phases.** Rewind then distinguishes its reverts from the user's hand edits (item 17), and turn-to-snapshot mapping no longer depends on a run record that a crashed run never wrote.
9. **Make `ownSubagentRuns` the default** and inherited runs the explicit opt-in; the fork double-count (item 42) is the second time this trap has been hit.
10. **One "the run's change" helper in the eval harness**, diffing against the fixture's base SHA, used by gold, degradations, ReviewSim and Cascade. Items 43, 47 and half of 49 fall out of it, and results become comparable across tools. Pair it with one infra-versus-model classification used by every path.
11. **A per-run process group and clean environment for harness and hook children.** Gold, hooks and background jobs inherit the login profile and outlive their run. Own group, group kill on timeout, `zsh -f`, explicit PATH.
12. **Fail loudly on config decode.** `EndpointStore`, `ProfileStore` and the app's `persist`/`saveEndpoints`/`saveProfile` all print and continue. `ModelPool.loadChecked` has the right shape; use it everywhere a save could follow a failed load.
13. **Normalize once.** Reasoning aliases ("off"/"none"), endpoint names and the model id's colon prefix each get parsed in several places with different rules; one normalizer each, used everywhere, removes items 12, 34 and the ToolForcing mismatch.
14. **Isolate the streaming row in the app.** ChatView's body reads `streaming`, so the whole transcript re-evaluates per publish; a child view that alone observes it bounds the per-frame work and makes the O(n²) `toolBoundary` scan harmless.
15. **Consider approvals as a pinned bar above the composer** with focus-scoped keys, like the escalation card, instead of rows in the lazy transcript (whose shortcuts exist only while the row does).
