# Adopt the process core, write the tools

Public Agent Skills for software development are plentiful but uneven. A handful of process skills are genuinely good, chiefly obra/superpowers for debugging, TDD, verification, receiving review, planning and git worktrees. Anthropic's and Trail of Bits' review and security workflows are the strongest for performing review because they filter false positives. Vendor rule packs (Vercel React, Supabase Postgres, HashiCorp Terraform) carry post-training-cutoff knowledge. Beyond those, most of the thousands of published skills are generic tutorials that restate what the model already knows. Coverage of TAXONOMY_v0 looks broad when you count skill names: about 52 of 77 items have several dedicated skills. It is narrow when you read the skills. Investigative and tool-heavy work (history archaeology, bisecting, codemods, regex, build debugging, flaky tests, memory and concurrency bugs, code comments) has weak or no coverage, so that is where a new library adds the most. The evaluation evidence is sobering. Curated skills raise software-engineering pass rates by only **+4.5 points** in the largest benchmark, one web-dev study found skills cut pass rates while raising token cost **72–394%**, and skills often go unused: **56%** non-invocation in Vercel's test. So the library should be small (about 30 visible skills), short per skill, routed rather than description-matched for knowledge packs, and every skill should be treated as a hypothesis to test per model against a no-skill baseline. The table at the end gives a per-item adopt/adapt/rewrite/write-new/skip call.

## One folder format now loads in every major coding agent

The Agent Skills format is deliberately tiny. A skill is a folder whose `SKILL.md` needs only a `name` (≤64 lowercase-hyphen characters, matching the directory) and a `description` (≤1,024 characters), with optional `license`, `compatibility`, `metadata` and experimental `allowed-tools`. Loading uses three-stage progressive disclosure: about 100 tokens of metadata at startup, a body recommended under 5,000 tokens and 500 lines, then `scripts/`, `references/` and `assets/` on demand ([agentskills.io spec](https://agentskills.io/specification)). Anthropic released it as an open standard in December 2025 ([Unite.ai](https://www.unite.ai/anthropic-opens-agent-skills-standard-continuing-its-pattern-of-building-industry-infrastructure)). Claude Code ([docs](https://code.claude.com/docs/en/skills)), Codex ([OpenAI](https://learn.chatgpt.com/docs/build-skills)), Gemini CLI ([docs](https://geminicli.com/docs/cli/skills/)), Cursor ([docs](https://cursor.com/docs/context/skills)), GitHub Copilot ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills)) and opencode ([docs](https://opencode.ai/docs/skills/)) all load it. **`.agents/skills/` is the closest thing to a universal path.** Codex, Gemini CLI, Cursor, Copilot and opencode read it, while Claude Code's documented locations are `.claude/skills/`, so a cross-harness library needs both paths or a symlink.

Two portability facts constrain library design more than the spec does. First, only the six spec fields are portable. opencode ignores everything else ([opencode](https://opencode.ai/docs/skills/)), and claude.ai/API uploads reject Claude Code's extension keys such as `context: fork` and `disable-model-invocation` as hard errors ([Claude Code docs](https://code.claude.com/docs/en/skills)). Second, harnesses ration the skill listing. **Codex caps the initial list at 2% of the context window, or 8,000 characters if the window is unknown, and silently shortens descriptions or drops skills beyond that** ([OpenAI](https://learn.chatgpt.com/docs/build-skills)). Claude Code truncates each description at 1,536 characters ([Claude Code docs](https://code.claude.com/docs/en/skills)). If all 77 taxonomy items became separate skills, Codex's default budget would leave about 100 characters per description. That arithmetic alone argues for merging items into fewer skills.

## Thousands of skills, three kinds, one converging process core

The public supply splits along the taxonomy's own Process/Knowledge/Tool lines.

**Vendor collections are mostly product-integration knowledge.** google/skills (~175 skills, Apache-2.0) covers Google Cloud products ([google/skills](https://github.com/google/skills)). microsoft/skills (~174, MIT) is dominated by per-language Azure SDK skills ([microsoft/skills](https://github.com/microsoft/skills)). Cloudflare (19, Apache-2.0), Supabase (2, MIT), HashiCorp (20, MPL-2.0), Stripe and Expo document their own platforms ([cloudflare/skills](https://github.com/cloudflare/skills); [supabase/agent-skills](https://github.com/supabase/agent-skills); [hashicorp/agent-skills](https://github.com/hashicorp/agent-skills); [Expo](https://docs.expo.dev/skills/)). Vercel's eight MIT skills add general web rule packs, react-best-practices and web-design-guidelines ([vercel-labs/agent-skills](https://github.com/vercel-labs/agent-skills)). anthropics/skills is famous (183.6k stars) but holds only about five dev skills, among them frontend-design, webapp-testing, mcp-builder and skill-creator, and it describes itself as demonstration material ([anthropics/skills](https://github.com/anthropics/skills)). Anthropic's real dev coverage lives in Claude Code plugins built from commands, subagents and hooks rather than portable SKILL.md files: code-review, feature-dev, pr-review-toolkit, commit-commands and security-guidance ([claude-plugins-official](https://github.com/anthropics/claude-plugins-official); [claude-code plugins](https://github.com/anthropics/claude-code/tree/main/plugins)). OpenAI's curated Codex set has the most general-purpose process tools of any vendor: gh-fix-ci, gh-address-comments, security-threat-model and cli-creator. The repo is now marked deprecated in favour of openai/plugins ([openai/skills](https://github.com/openai/skills)). Cursor publishes no general library; its equivalent is `.cursor/rules`, now convertible with `/migrate-to-skills` ([Cursor](https://cursor.com/docs/context/skills)).

**Community process packs are small, opinionated and the most installed.** obra/superpowers has 15 skills, MIT, about 305k stars, and supports 16 harnesses. It packages a full methodology: brainstorm, worktree, plan, execute, TDD, review, finish branch ([GitHub API](https://api.github.com/repos/obra/superpowers); [repo](https://github.com/obra/superpowers)). mattpocock/skills (38 skills, MIT) holds 13 of the top 30 slots on the skills.sh install leaderboard. Its top entries are grill-me (1.4M installs), tdd (1.1M) and handoff (1.0M) ([skills.sh](https://skills.sh)). addyosmani/agent-skills (25, MIT) spans spec, plan, implementation, review, CI and docs ([GitHub API](https://api.github.com/repos/addyosmani/agent-skills)). garrytan/gstack (about 60 skills, MIT) and EveryInc's compound-engineering plugin (about 37 skills, MIT) are role- and workflow-heavy ([gstack](https://api.github.com/repos/garrytan/gstack); [compound-engineering](https://api.github.com/repos/EveryInc/compound-engineering-plugin)). Across these packs the same core recurs: interview or brainstorm, spec, plan, incremental implementation, TDD, debug, review, verify, hand off. **That convergence is the strongest signal of which process skills practitioners actually want.**

**Knowledge marketplaces are wide and shallow.** wshobson/agents has 185 skills in 94 plugins, generated for seven harnesses ([repo](https://github.com/wshobson/agents)). affaan-m/ECC has 314 unique skill names, each duplicated per harness ([GitHub API](https://api.github.com/repos/affaan-m/ECC)). Jeffallan has 67 "pro" and "expert" skills, and sickn33 aggregates 2,866 unique names, many of them copies ([topic search](https://api.github.com/search/repositories?q=topic:agent-skills&sort=stars)). They show what exists, not what is good. One specialist pack stands out: **trailofbits/skills (97 skills) is the deepest source for security review, static analysis, fuzzing and property-based testing, but it is licensed CC-BY-SA-4.0**, so adapted text inherits share-alike terms ([GitHub API](https://api.github.com/repos/trailofbits/skills)).

Popularity numbers deserve suspicion. Star counts near 300k for superpowers, mattpocock and ECC, and 380k for an unrelated repo, could not be checked for inflation, and one source reports superpowers tripling from about 93k to about 298k stars in seven months ([kunalganglani.com](https://www.kunalganglani.com/blog/superpowers-agentic-skills-framework)). Install counts and roundup citations agree on a narrower point: small process packs get reused, and short skills get reused most. The most-installed mattpocock skills have a median SKILL.md of 3.6 KB, and grill-me is 157 bytes ([mattpocock tree](https://api.github.com/repos/mattpocock/skills/git/trees/HEAD?recursive=1)).

## Coverage is broad by name and narrow by quality

A name-and-description match across 4,713 skill entries in 14 collections rates 52 taxonomy items as well covered, 22 as thin and 3 as uncovered: **history archaeology (#3), regex and text processing (#21) and codemods (#65)**. That search found **zero** skills named for git bisect, blame or history, codemods (ast-grep, OpenRewrite, comby), characterization tests, stack-trace or log analysis, core dumps, flame graphs, memory profiling, deadlocks or docstrings ([combined trees, e.g. sickn33](https://api.github.com/repos/sickn33/agentic-awesome-skills/git/trees/HEAD?recursive=1)). The pattern is consistent. The community concentrates on the front of the lifecycle (clarify, plan, implement, review) and on stack knowledge. It neglects investigative and tool-driven work. Several items exist only inside broader skills. Root-cause tracing, flaky-test polluter bisection and condition-based waiting, for example, are all supporting files inside superpowers' systematic-debugging ([tree](https://github.com/obra/superpowers/tree/main/skills/systematic-debugging)), where they are hard to find or invoke on their own.

Reading the skills, rather than counting names, moves several "good" items down. Error handling (#15), threat modeling (#41), containers (#55), observability (#57), packaging and release (#48), and all documentation items (#60–63) have plenty of named skills but **no authoritative, cross-language, high-quality one**. Registry reviews repeatedly fault the community versions as generic. Tessl's LLM judge said a Go patterns skill "covers too many topics inline" that Claude already knows, and scored a golang-expert skill 53% ([Tessl](https://tessl.io/registry/skills/github/RightNow-AI/openfang/golang-expert/review)). It found that wshobson's bash-defensive-patterns defers its content to a playbook that is not present ([Tessl](https://tessl.io/registry/skills/github/sickn33/antigravity-awesome-skills/bash-defensive-patterns/quality)). Language packs show the same split. Python and C++ have expert-authored packs (Trail of Bits modern-python and modern-cpp), Swift has Paul Hudson's swiftui-pro, and Kotlin has a JetBrains incubator. **Go, TypeScript, Java and shell have only community skills** ([ToB modern-python](https://raw.githubusercontent.com/trailofbits/skills/main/plugins/modern-python/skills/modern-python/SKILL.md); [swiftui-pro](https://raw.githubusercontent.com/twostraws/SwiftUI-Agent-Skill/main/swiftui-pro/SKILL.md)). Framework coverage is strong where vendors publish (React/Next, Supabase, Cloudflare, Expo, Terraform) and absent for Django, Rails, Spring and Express.

The community also covers ground the taxonomy omits. Candidate additions:

- **Destructive-action guardrails.** mattpocock's git-guardrails hooks and gstack's careful, guard and freeze skills.
- **Adversarial or persona plan review.** gstack's plan-*-review skills and addyosmani's doubt-driven-development.
- **Cross-model second opinions.** Trail of Bits second-opinion.
- **Issue triage.**
- **"Capture learnings" loops.** compound-engineering's ce-compound.

Sources: [gstack tree](https://api.github.com/repos/garrytan/gstack/git/trees/HEAD?recursive=1); [mattpocock tree](https://api.github.com/repos/mattpocock/skills/git/trees/HEAD?recursive=1); [trailofbits tree](https://api.github.com/repos/trailofbits/skills/git/trees/HEAD?recursive=1). Guardrails are better implemented as hooks than as skills, because a skill is advice the model can ignore, while a hook is enforced by the harness.

## Quality tracks enforcement, false-positive control and shipped scripts

Reading the full text of the best-known skills shows four designs that work and one that does not.

**Discipline skills work when they name the failure and block the rationalization.** Superpowers uses one recognizable template: a trigger-only description, an "Iron Law", phase gates, a rationalization table and a red-flags list, usually in 3–10 KB. systematic-debugging forbids fixes before root-cause investigation. It requires instrumentation at every component boundary in multi-layer systems, and after three failed fixes it stops and questions the architecture ([SKILL.md](https://github.com/obra/superpowers/blob/main/skills/systematic-debugging/SKILL.md)). test-driven-development requires watching each test fail for the expected reason and deleting code written before its test ([SKILL.md](https://github.com/obra/superpowers/blob/main/skills/test-driven-development/SKILL.md)). verification-before-completion maps each claim to the fresh evidence it needs; "bug fixed", for example, requires re-testing the original symptom ([SKILL.md](https://github.com/obra/superpowers/blob/main/skills/verification-before-completion/SKILL.md)). receiving-code-review bans performative agreement and requires verifying each comment against the codebase before implementing it. It is the only serious skill for item #29 ([SKILL.md](https://github.com/obra/superpowers/blob/main/skills/receiving-code-review/SKILL.md)). writing-plans and executing-plans add interface blocks per task, a compaction-proof progress ledger, and "ledgered rulings" for plan conflicts ([writing-plans](https://github.com/obra/superpowers/blob/main/skills/writing-plans/SKILL.md); [executing-plans](https://github.com/obra/superpowers/blob/main/skills/executing-plans/SKILL.md)).

Their weaknesses are consistent:

- **No proportionality.** A typo gets the full four-phase gate.
- **No autonomous-mode path.** "Discuss with your human partner" fails when no human is present.
- **Narrow examples.** Examples are TypeScript-only.
- **Gaps in coverage.** There is no git bisect, debugger or concurrency branch, and no characterization-test path for legacy code.
- **Coupling.** The plan pipeline depends on superpowers' own directories and scripts, so it is hard to adopt piecemeal.

**Review skills work when they distrust their own findings.** Anthropic's `/code-review` command runs parallel reviewers and then re-checks every flagged issue with a separate validation subagent, dropping anything unconfirmed. It flags only compile failures, logic that is wrong for every input, and quotable rule violations, on the grounds that "False positives erode trust" ([code-review.md](https://github.com/anthropics/claude-code/blob/main/plugins/code-review/commands/code-review.md)). The `/security-review` command requires an exploit scenario per finding, applies 17+ hard exclusions, and drops anything below 8/10 confidence on a second pass ([security-review.md](https://github.com/anthropics/claude-code-security-review/blob/main/.claude/commands/security-review.md)). Trail of Bits goes further. differential-review adds git blame on removed security code and counts callers to estimate blast radius ([SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/differential-review/skills/differential-review/SKILL.md)), and fp-check builds in the premise that LLMs over-report bugs ([SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/fp-check/skills/fp-check/SKILL.md)). Superpowers' reviewer prompt has nothing comparable. Its strengths are plan alignment and a "declined to judge" list ([code-reviewer.md](https://github.com/obra/superpowers/blob/main/skills/requesting-code-review/code-reviewer.md)). The best review skill would merge the two, but Anthropic's versions are slash commands that depend on subagents and `gh`, so they need conversion to a portable SKILL.md. Anthropic's code-review README also still describes an older design than the command implements.

**Knowledge skills work when they are opinionated, ranked and post-cutoff.** The strong ones share a shape: a narrow stance, an anti-pattern→replacement table, a decision tree, exact commands or flags, and per-rule reference files. Vercel's react-best-practices ranks 70 rules by impact in eight categories, one file per rule with incorrect and correct code ([SKILL.md](https://raw.githubusercontent.com/vercel-labs/agent-skills/main/skills/react-best-practices/SKILL.md)). Supabase's Postgres skill does the same with EXPLAIN output ([SKILL.md](https://raw.githubusercontent.com/supabase/agent-skills/main/skills/supabase-postgres-best-practices/SKILL.md)). Trail of Bits' modern-python prescribes uv, ruff and ty with a migration table ([SKILL.md](https://raw.githubusercontent.com/trailofbits/skills/main/plugins/modern-python/skills/modern-python/SKILL.md)). **Tool skills work when a script carries a defined exit contract.** Examples are OpenAI's gh-fix-ci, whose `inspect_pr_checks.py` exits non-zero while checks fail ([SKILL.md](https://raw.githubusercontent.com/openai/skills/main/skills/.curated/gh-fix-ci/SKILL.md)); Anthropic's webapp-testing, whose `with_server.py` manages server lifecycle under the rule "treat scripts as black boxes" ([SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/webapp-testing/SKILL.md)); and Trail of Bits' supply-chain-risk-auditor, which marks each criterion clean, flagged or "unassessable" rather than guessing ([SKILL.md](https://raw.githubusercontent.com/trailofbits/skills/main/plugins/supply-chain-risk-auditor/skills/supply-chain-risk-auditor/SKILL.md)).

**What does not work is the human tutorial.** wshobson's debugging-strategies recommends rubber-duck debugging and "take breaks", has no gate or stop rule, and uses a "Master systematic debugging" marketing description instead of a trigger ([SKILL.md](https://github.com/wshobson/agents/blob/main/plugins/developer-essentials/skills/debugging-strategies/SKILL.md)). Its code-review-excellence sets review-within-24-hours norms for human teams ([SKILL.md](https://github.com/wshobson/agents/blob/main/plugins/developer-essentials/skills/code-review-excellence/SKILL.md)). ECC's tdd-workflow imposes an 80% coverage target that invites coverage padding ([SKILL.md](https://github.com/affaan-m/ECC/blob/main/skills/tdd-workflow/SKILL.md)). These skills add tokens the model must read but change little of what it does. Two areas have no good canonical skill at all. The cleanest refactoring skill found is an obscure Rails skill: igmarin's refactor-code, 28 stars, which requires characterization tests before any structural change ([SKILL.md](https://github.com/igmarin/rails-agent-skills/blob/main/skills/refactor-code/SKILL.md)). Anthropic's `/commit` is 0.6 KB with no guidance on atomicity or message quality ([commit.md](https://github.com/anthropics/claude-code/blob/main/plugins/commit-commands/commands/commit.md)).

## Evaluations show small software gains and real downside

The most rigorous benchmark, SkillsBench, ran 84 tasks across 11 domains on seven agent-model configurations, five runs each, graded by deterministic tests. **Curated skills raised average pass rates from 24.3% to 40.6%, but Software Engineering gained least: 34.4% to 38.9%, +4.5 points.** Self-generated skills scored below no skills, 16 of 84 tasks got worse, and "comprehensive" skills averaged **−2.9 points** against +17 to +19 for compact or detailed ones ([arXiv 2602.12670](https://arxiv.org/html/2602.12670v1)). Supplying four or more skills cut the gain to +5.9 points, against about +18 for one to three. The paper is internally inconsistent on some totals, so treat the exact figures as approximate. Smaller models gained: Haiku 4.5 with skills (27.7%) beat Opus 4.5 without them (22.0%).

Two software-specific studies are more negative. Evaluating AGENTS.md files on SWE-bench Lite and a new 138-instance benchmark, Gloaguen et al. found that **LLM-generated context files lowered success and raised cost about 20–23%**, while developer-written files raised success about 4% at up to 19% extra cost ([arXiv 2602.11988](https://arxiv.org/html/2602.11988v1)). WebDev-Skills-Bench, known from its abstract only, injected 31 public web-dev skills into 1,000 tasks. It found **Pass@2 fell 1.3–4.2% while token cost rose 72–394%**, and only 17–36% of skill-project pairs improved. A length-matched irrelevant skill reproduced most of the loss for some models. Anti-pattern rules beat example-heavy content, and skill rankings transferred weakly across models ([arXiv 2608.23067](https://arxiv.org/abs/2608.23067)). Vercel's own eval found that **a Next.js 16 skill was never invoked in 56% of runs**, scoring the same as no docs (53%). An explicit instruction to use it raised that to 79%, and a compressed 8 KB docs index in AGENTS.md scored 100% ([Vercel](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Vercel did not disclose the model or task count.

Library size is its own risk. Two studies seen only as snippets report selection accuracy above 90% with 20 or fewer skills, falling to about 20% at 200, driven by confusable descriptions ([arXiv 2601.04748](https://arxiv.org/html/2601.04748v1)). They also report up to a 21% performance drop at 202 skills from "skill shadowing", meaning wrong selection rather than context size ([ICML 2026](https://icml.cc/virtual/2026/77891)). A third reports that selection breaks down at about 26 distractor skills for DeepSeek V4 Flash but about 194 for Opus 4.7 ([arXiv 2607.01874](https://arxiv.org/pdf/2607.01874)). **Smaller models hit the library-size ceiling much earlier**, which matters if the library will run on local models. Security is the last cost. SkillInject reports up to 80% attack success for prompt injection through skill files ([arXiv 2602.20156](https://arxiv.org/abs/2602.20156)), and a Snyk audit (seen as a snippet) found critical issues in 13.4% of about 4,000 marketplace skills ([Snyk](https://snyk.io/de/blog/toxicskills-malicious-ai-agent-skills-clawhub/)). Importing from aggregators therefore requires reading the bundled scripts, not only SKILL.md.

These results support a clear position. **Skills help most where the model lacks knowledge or reliably misbehaves**, such as post-cutoff APIs, thinly documented repos, niche tools, and known agent failure modes like premature "done". They hurt when they restate priors or flood context. No public skill in any taxonomy area has published outcome-level evidence comparing bugs fixed with and without the skill across N tasks. Superpowers' evidence is self-run pressure scenarios, plus a few small controlled micro-tests on wording ([eval results](https://github.com/obra/superpowers/blob/main/docs/superpowers/specs/2026-07-06-sdd-plan-scoped-workspace-eval-results.md)). Anthropic publishes no precision or recall for its review commands.

## Test each skill as a hypothesis about one model

The sources mostly agree on authoring:

- **The description is the trigger.** It must be specific and keyword-rich.
- **Keep the body short.** Under 500 lines, with references one level deep.
- **Match freedom to fragility.** Prose for open judgment calls, exact scripts for brittle operations.
- **Assume the model is already smart.** Add only what it lacks.

Sources: [Anthropic best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); [OpenAI](https://learn.chatgpt.com/docs/build-skills). They disagree on two points. Anthropic's skill-creator says descriptions should be "a little bit pushy" because Claude undertriggers, and calls all-caps MUST and NEVER a "yellow flag" ([skill-creator](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)). Superpowers says descriptions must state only triggering conditions, never a summary of the workflow, because agents follow the summary instead of reading the skill, and it uses capitalized Iron Laws ([writing-skills](https://github.com/obra/superpowers/blob/main/skills/writing-skills/SKILL.md)). OpenAI adds that descriptions should state when **not** to trigger and front-load keywords so they survive truncation ([OpenAI](https://learn.chatgpt.com/docs/build-skills)).

Superpowers' own micro-tests (opus, 5 reps per phrasing) partly settle the MUST question. A composition prohibition ("don't restate the brief") produced more of the unwanted behavior than no guidance (4.4 vs 3.6 restated values). A positive recipe produced 3.0 with zero variance. A discrete prohibition ("do not ask the reviewer to re-run tests") cut violations from 3/5 to 0/5 ([spec](https://github.com/obra/superpowers/blob/main/docs/superpowers/specs/2026-06-10-positive-instruction-redesign-design.md)). The resulting rule, **"match the form to the failure"**, is the most actionable authoring finding in the corpus. Use discrete prohibitions and rationalization tables for discipline failures, explained positive recipes for output-shape failures, required template slots for omissions, and conditionals keyed to observable predicates. The trigger disagreement is empirical, and near-miss trigger evals decide it per skill.

For testing, two published methods complement each other. **Anthropic's skill-creator** measures triggering with about 20 labelled queries (half positives, half near-miss negatives), each run 3 times, with a 60/40 train/test split for description optimization. It measures effect with paired with-skill and baseline runs, assertion grading, and mean ± stddev for pass rate, time and tokens. It also flags non-discriminating assertions that pass regardless of the skill ([skill-creator](https://raw.githubusercontent.com/anthropics/skills/main/skills/skill-creator/SKILL.md)). **Superpowers' RED-GREEN-REFACTOR** first runs a pressure scenario on a subagent without the skill, combining time, sunk-cost, authority and exhaustion pressures. It records the agent's rationalizations verbatim, writes the minimal skill to counter them, and re-runs. It tests each skill type against its own target: compliance under stress for discipline skills, transfer to a new scenario for technique skills, correct retrieval for reference skills ([writing-skills](https://raw.githubusercontent.com/obra/superpowers/main/skills/writing-skills/SKILL.md)). Its author found early subagent quizzes gave false perfect scores, and that realistic pressure scenarios did not ([blog.fsck.com](https://blog.fsck.com/2025/10/09/superpowers/)). Anthropic's checklist asks for at least three evals and testing on every target model, because "what works perfectly for Opus might need more detail for Haiku" ([Anthropic](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)).

Combining these with the benchmark findings gives a minimum test protocol for each skill:

1. **Trigger precision and recall**, using near-miss negatives and repeats.
2. **Task outcome with the skill force-loaded against no skill**, which isolates "helps when used" from "gets used".
3. **End-to-end runs with natural triggering.**
4. **A length-matched irrelevant-skill control**, borrowed from WebDev-Skills-Bench.
5. **Cost.** Report tokens and steps alongside pass rate.
6. **Model coverage.** Run on every target model, including small local ones.

Two library-level tests come on top: selection accuracy with the whole library installed at full size, and a security read of every bundled script.

## Conclusion

The question has shifted from "which skills exist" to "which skills earn their tokens". The public ecosystem supplies an excellent process spine, mostly superpowers plus Anthropic's review designs, and good vendor knowledge. The rest of the volume is noise that the evidence says can make agents slower and slightly worse. The taxonomy's Tool items are the clearest place for original work: bisect, archaeology, codemods, build debugging, profiling and flaky tests. They are uncovered, and they are where scripts with exit contracts beat model priors. The process items, by contrast, can be adapted rather than invented. The work there is adding proportionality, autonomous-mode behavior and decoupling, not new methodology.

Two consequences follow for building the library. First, size and routing are design constraints. Selection degrades sharply with library size, earlier for small models, and Codex rations description space. So the target should be about 30 merged skills, plus vendor Knowledge packs reached through an explicit index rather than description matching. Second, no public skill has outcome-level evidence on software tasks. A library that ships every skill with a trigger eval, a force-loaded baseline comparison and a length-matched control, run on each target model, would be the first to know whether its skills help. That evidence would be worth more than any individual skill.
